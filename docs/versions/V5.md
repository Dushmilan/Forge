# V5 — Heartbeats + failure recovery

**Go concepts:** `time.Ticker` driven by a goroutine that is stopped and joined,
`time.Time` persisted through JSON (pointer fields make "never happened"
distinguishable from "happened at the zero instant"), a status state machine
expressed as an explicit transition table and enforced at the one place that
writes, and startup reconciliation — turning an on-disk snapshot into a running
system.

**Why this version exists:** V4 gives a *live* job a lifetime, but the process
has no memory. If Forge dies, every record left `running` stays `running`
forever, and every record left `pending` in the channel buffer never runs
again. V5 makes the store the source of truth across restarts: a job refreshes
a heartbeat while it executes, and a recovery pass at startup repairs what the
previous process left behind. It also makes the lifecycle explicit, so
recovery cannot invent a state the rest of the system does not understand.

## What is and is not a lease

V5 records liveness; it does not yet *enforce a lease*. A running record is
reclaimed at startup unconditionally, because in a single-process Forge it can
only be an orphan. Comparing heartbeat age against a timeout is what a second
process would need before deciding a job is dead — that decision requires
multiple processes, and arrives with V11's horizontal scaling. Recording the
heartbeat now is what makes that later decision possible; pretending to enforce
it now would be machinery with no honest failure mode to catch.

## The state machine

`job.Status.CanTransition(to)` is the single authority for legal moves:

| From | To | Why |
|---|---|---|
| `pending` | `running`, `cancelled`, `failed` | a worker claims it; a tombstone cancels it; a spent budget fails it before it starts |
| `running` | `succeeded`, `failed`, `cancelled` | V4's outcomes |
| `running` | `pending` | **recovery only**: interrupted by a restart |
| terminal | nothing different | a terminal status is a final answer |
| any | itself | a worker re-saves `running` on every attempt |

`store.Save` enforces the table inside its existing locked read-modify-write:
it loads the current record, rejects an illegal move with an error that wraps
`job.ErrInvalidTransition`, and writes nothing. Creating a record that did not
exist is not a transition — it is a seed — so V1's store tests and direct test
setup keep working. The result is that the state machine is not a comment
somewhere; an illegal write fails.

## Field ownership: heartbeat vs record

`Record` gains one field:

```go
LastHeartbeat *time.Time `json:"last_heartbeat,omitempty"`
```

A pointer, not a `time.Time`: `nil` means "this job has never been running" and
vanishes from the JSON, while a zero `time.Time` would serialize as
`0001-01-01T00:00:00Z` on every pending job.

The heartbeat has a single writer — `store.Heartbeat(id, at)` — and `Save`
never writes the value: for an existing record it always keeps the stored
heartbeat, whatever the incoming record carries. This is not cosmetic. The
worker writes whole records (including a snapshot recovered from disk that
holds an older timestamp); the heartbeat goroutine writes one field. Without
the ownership rule, a worker save racing a tick would rewind liveness, and a
tick racing the final save could resurrect a `running` record over a finished
one. Two writers, two fields, one mutex.

## Deliverables

- `internal/job`
  - `ErrInvalidTransition` sentinel; `Status.CanTransition(to Status) bool`
    backed by one table, with same→same allowed.
- `internal/store`
  - `Record.LastHeartbeat *time.Time` (`json:"last_heartbeat,omitempty"`).
  - `Save` validates transitions against the stored record and never writes
    `LastHeartbeat` for an existing record (the stored value wins; only
    `Heartbeat` advances it). A `null` document is rejected as corruption
    rather than loaded as an empty store.
  - `Heartbeat(id, at time.Time) error` updates only the timestamp; it returns
    a wrapped `ErrNotRunning` when the record exists but is not `running` and
    a wrapped `ErrNotFound` when it does not exist.
  - `List() ([]Record, error)` returns every record ordered by id, for recovery.
  - The atomic temp-file + rename write is factored into one helper shared by
    `Save` and `Heartbeat`, so both write the same way.
- `internal/worker`
  - `Config.Heartbeat time.Duration`; zero disables heartbeats (tests), and
    `runServe` always passes a positive value.
  - `Handle` resumes at `rec.Attempts + 1`; a record whose attempts are already
    exhausted is marked `failed` without calling the runner.
  - Each attempt starts one heartbeat goroutine (`time.NewTicker`, `defer
    t.Stop()`) that calls `store.Heartbeat`. It is stopped and **joined**
    before the attempt's result is saved. `ErrNotRunning`/`ErrNotFound` end the
    goroutine quietly; any other error is reported to `stderr` once and ends it.
- `internal/recovery` (new package)
  - `Config{MaxAttempts int}` and
    `Recover(st *store.Store, cfg Config) ([]store.Record, error)`.
  - Repair table:

    | On-disk | Attempts | Action |
    |---|---|---|
    | `pending` | any | requeue unchanged |
    | `running` | `< MaxAttempts` | → `pending`, `Err` names the interrupted attempt, requeue |
    | `running` | `>= MaxAttempts` | → `failed`, `Err` says the attempts were exhausted |
    | terminal | any | ignored |

  - Any store or save failure aborts with an error: unknown startup state is
    loud, not guessed.
- `cmd/forge`
  - `serve` gains `-heartbeat-interval` (default `1s`, must be `> 0`; invalid
    values exit `2`). It is validated before any goroutine starts.
  - Startup order: recover → start the pool → enqueue the returned records.
    Starting the pool first is what keeps a recovery set larger than the
    queue's 64 slots from deadlocking; enqueue failures are reported and the
    record stays `pending` for the next start.
  - `forge: recovered N job(s)` on `stderr` when N > 0.
  - A recovery error prints and exits `1`: serving on a store whose state we
    could not repair would hide the problem.
- `internal/api`
  - No code changes. `GET /jobs/{id}` now also shows `last_heartbeat` moving
    while a job runs.
- `README.md`, `docs/LEARNING.md`
  - README status, `serve` flags, and a V5 section; LEARNING entry in the
    established format.

## Semantics

- **At-least-once.** A job interrupted after its side effect but before its
  final save runs again. Exactly-once is V6's idempotency story.
- **A crash costs one attempt.** The interrupted attempt was already counted
  when it started, so recovery resumes at the next one. A job that keeps
  killing the process exhausts its budget and ends `failed` instead of
  crash-looping forever.
- **Recovery uses the current budget.** `MaxAttempts` comes from the flags of
  the process doing the recovering; a restart with a smaller `-max-attempts`
  can fail a previously viable job.
- **Running records are orphans at startup.** No heartbeat-age comparison is
  used to decide, because no other process exists to own a recent one.
- **Only the worker writes statuses while running.** Recovery writes statuses
  only before the pool starts; heartbeat writes only timestamps at any time.

## Test checklist

- Job: the transition table is legal/illegal as specified (table-driven with
  `t.Run`); `ErrInvalidTransition` survives wrapping (`errors.Is`).
- Store: `succeeded → running` is rejected and the file is unchanged;
  `running → pending` is accepted (recovery edge); same→same is accepted.
- Store: `Heartbeat` changes only `LastHeartbeat`; a heartbeat on a terminal
  record returns `ErrNotRunning` and writes nothing; on a missing id returns
  `ErrNotFound`.
- Store: `Save` never changes a stored heartbeat (a nil or older incoming
  value is ignored), and a fresh record has nil.
- Store: a `null` jobs.json is an error for `Get`, `List`, and `Save` — never
  a panic and never a silently empty store.
- Store: `List` returns records ordered by id.
- Worker: a record saved with `Attempts = 1` starts at attempt 2 (runner call
  count and final `Attempts` pinned); a record at `MaxAttempts` calls the
  runner zero times and ends `failed`.
- Worker: while a gated runner blocks, heartbeats advance (poll the store to a
  deadline — no `time.Sleep`); after `Handle` returns, no further heartbeat is
  written (the join is proven).
- Worker: a heartbeat write racing the final save passes under `-race` and the
  final status is never overwritten.
- Recovery: the four-row table; repaired records are returned in id order;
  terminal records are never touched; a corrupt store returns an error.
- CLI: `-heartbeat-interval 0`, `-1s`, and `nope` each exit `2` with a message
  on `stderr` (table-driven).
- e2e: seed `jobs.json` with a `running` record at `Attempts = 1`, start
  `serve`, poll `GET` until `succeeded` and assert `Attempts == 2`; seed a
  `pending` record and assert it runs.
- All V0–V4 tests still pass.

## Out of scope

A periodic lease reaper or stale-heartbeat cancellation while the process
lives, `-heartbeat-timeout`, `StartedAt`/`FinishedAt`, attempt history,
`GET /jobs` listing, process-kill e2e tests, multi-process coordination
(V11), exactly-once execution (V6).
